# ADR-030: FORGE Configuration Model

**Date:** 2026-03-06
**Status:** Accepted
**Decision Makers:** sati orchestrator, council (minimax — pending)
**Supersedes:** `.forgerc` shell-sourceable config (v2)

---

## Context

forge-v2 used `~/.forgerc`, a shell-sourceable file with env var assignments:
```bash
FORGE_API_URL=http://prya.queue-great.ts.net:8080
FORGE_NODE_ID=sati
FORGE_ROOT=/home/bogdan/FORGE
```

forge-v3 uses env vars only — no config file equivalent. This means:
- Every daemon restart requires passing ~6 env vars by hand or scripting
- No single source of truth for how a node connects to the control plane
- Agents have no `forge init` to set themselves up
- New nodes require documentation lookup, not self-service

Additionally, prya is now the designated control plane. All other nodes need to know:
1. Where the control plane lives (`http://prya:8081`)
2. Their own identity (`NODE_ID=sati`)
3. Optionally: auth token, FORGE_ROOT, preferred log level

---

## Decision

### 1. Config file: `~/.forge/config.toml`

TOML format. Managed by `forge init` wizard and `forge config set/get`.

```toml
# ~/.forge/config.toml
# Generated by: forge init

[node]
id       = "sati"           # This node's identity in the mesh
role     = "worker"         # "control_plane" | "worker" | "auto"

[control_plane]
url      = "http://prya:8081"   # Primary control plane URL (Magic DNS)
fallback = ""                    # Optional fallback URL
timeout  = "10s"                 # Connection timeout before error

[auth]
token    = ""               # API token (empty = local mode, no auth)

[paths]
forge_root = "/home/bogdan/FORGE"
log_file   = "/tmp/forge-{node.id}.log"

[daemon]
port    = 8081
ws_port = 8082
db_path = ""    # empty = {forge_root}/.forge/forge-v3.db
known_peers = ["http://nova:8081", "http://gaea:8081"]

[ui]
color  = true
pager  = "less"
output = "text"   # "text" | "json" | "yaml"
```

### 2. Precedence (highest to lowest)

```
CLI flags  >  ENV vars  >  ~/.forge/config.toml  >  built-in defaults
```

ENV vars override config file so existing scripts and `export NODE_ID=...` patterns keep working.

### 3. `forge init` wizard

Interactive setup for new nodes and new agents:

```
$ forge init

  FORGE Setup Wizard
  ──────────────────
  ? Are you setting up a (c)ontrol plane or (w)orker node? w
  ? Control plane URL [http://prya:8081]: 
  ? Your node ID [sati (auto-detected from hostname)]: 
  ? FORGE_ROOT [/home/bogdan/FORGE (auto-detected)]: 
  ? API token (leave blank for local/Tailscale-only mode): 
  
  Checking connection to http://prya:8081... ✓ connected
  
  Config written to ~/.forge/config.toml
  Run `forge daemon start` to start the local daemon.
  Run `forge status` to verify fleet connectivity.
```

### 4. Env var shim (backward compat)

`forge env` prints shell-sourceable exports from the config:
```bash
eval "$(forge env)"   # replaces source ~/.forgerc
```

### 5. Error handling when control plane unreachable

Every command that needs the control plane:
```
$ forge tasks list

  Error: control plane unreachable
  
  URL: http://prya:8081 (from ~/.forge/config.toml)
  
  Possible fixes:
    • Check Tailscale: tailscale status | grep prya
    • Start prya daemon: ssh prya "bash bin/forge-v3-start-prya"
    • Use local mode: forge --local tasks list
    • Change control plane: forge config set control_plane.url http://sati:8081
```

---

## Consequences

- **forge init** replaces manual env var setup
- `~/.forgerc` is deprecated but still sourced if `~/.forge/config.toml` is absent (grace period: 2 sprints)
- All `forge-v3-start-*` bin scripts become redundant — replaced by `forge daemon start --node prya`
- `viper` is added as a Go dependency for config loading
